# v2.4.6

First CI (issue #13): `.github/workflows/build.yml` runs the core test
suite (`tests/run_tests.sh`, unchanged and self-contained) and compiles
BOTH firmware variants on every push and PR, from a pinned toolchain —
arduino-cli 1.5.1, esp32 core 3.3.11, TFT_eSPI 2.5.43, the same versions
the README documents as hardware-tested. Compilation is the whole gate:
no flashing, no hardware in CI; uploads and anything touching a real
board stay manual.

Before this, nothing in the repo verified that a push or PR even compiled
for either variant — a header rename or a bad `#include` surfaced only
when the next person flashed. Each run uploads both binaries as
sha-named artifacts.

The build job compiles from the `DiceSeed/` subdirectory per the v2.4.1
layout (compiling from the repo root reproduces the stranded-header
failure that layout fix was cut for — noted in the YAML so a future
cleanup cannot silently regress it). No firmware change.
