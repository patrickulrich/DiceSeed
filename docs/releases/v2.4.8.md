# v2.4.8

Release artifacts and verification, rebuilt. No change to the seed
algorithm — `diceseed_core.h`, the wordlist, and the test vectors are
byte-for-byte identical to v2.4.7, so the same physical rolls produce
the same mnemonic, compat and classic alike.

## One file, one address, one command

Every release `.bin` is now a **complete image** — bootloader, partition
table, and application together — flashed at `0x0`. Installing DiceSeed,
new board or update, is the same single command:

```sh
esptool write-flash 0x0 diceseed-vX.Y.Z-compat.bin
```

Previously the release files were application-only images (updates at
`0x10000`), and a blank board needed a one-time toolchain install. The
merged image closes that gap with no size cost worth caring about: the
core pads its merged output to the full 16MB flash, so the build trims
the trailing `0xFF` filler (the erased state — removing it is lossless),
leaving a ~450KB artifact versus ~390KB for the app alone. Flashing it
is equivalent, region for region, to what `arduino-cli upload` has
always written on every development upload.

A failed flash is never a dead board: the ESP32-S3's download mode lives
in silicon (hold BOOT while pressing RST, or while plugging in), so an
interrupted write is recovered by flashing again. For a second-hand
board or a provably clean chip, `esptool erase-chip` first wipes all
16MB; ordinary installs never need it — DiceSeed keeps secrets in RAM
only, so updates leave nothing behind.

## Note for anyone who downloaded v2.4.7

The v2.4.7 release is withdrawn. Its files were application-only
images and share names with v2.4.8's complete images — flash v2.4.8 the
standard way, at `0x0`, and it fully supersedes them.

## Opt-in signed releases

The pipeline now carries PGP signing as a capability: where a
maintainer has configured a `SIGNING_KEY` secret in the `release`
environment, each release gains a detached signature over
`SHA-256SUMS` and a signed annotated tag; where none is configured —
including this repo and any fork — releases publish unsigned with
hashes only, exactly as before, and nothing breaks. Enabling it is
three steps with zero code changes, documented in `docs/signing.md`.
