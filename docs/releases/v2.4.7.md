# v2.4.7

Released 2026-08-31. Everything new since v2.4.1: four tracker issues plus a
build/release pipeline. No change to the seed algorithm — `diceseed_core.h`,
the wordlist, and the test vectors are byte-for-byte identical to v2.4.1, so
the same physical rolls produce the same mnemonic as every 2.x build, compat
and classic alike.

## Touch boards

- Roll entry (v2.4.2, issue #10): the two-tap contract is finally visible.
  A first tap outlines the chosen cell in bold white (double white border,
  white digit); confirming — a second tap on that cell, or BTN2 — flashes
  the cell green for ~250 ms before the screen advances. Both commit paths
  flash identically. Green now means exactly one thing on this screen:
  "this value just entered rolls[]".
- Result flow (v2.4.5, issue #15): the raw-entropy hex view is a guaranteed
  stop. After the last word page, `>` (or BTN2) opens the hex screen before
  the backup quiz; `<` returns to the words, `>` starts the quiz. BTN1 no
  longer toggles the hex view on Touch boards — it mirrors `<` (back a
  page / back to words), per the buttons-mirror-cells rule.
- The menu cells, quiz cells, and non-touch digit keep their established
  white/green language, unchanged.

## Non-Touch boards

- Button markers (v2.4.3, issue #12): every button-driven screen carries a
  small "1" and "2" with an edge tick at the far right, aligned with the
  physical buttons — BTN2/GPIO14 top-right, BTN1/GPIO0 bottom-right
  (hardware-verified). The bottom hints say what each button does; the
  markers say which physical button is which. Everything else on a
  non-Touch board behaves exactly as in v2.4.1.

## Backup verification — both boards (v2.4.4, issue #14)

The post-roll quiz now checks every word (12 or 24; through v2.4.3 it
spot-checked 3 checkpoints). Per-word mechanics are unchanged: three blind
candidates, right/wrong feedback immediately after each pick. After the
last word, a summary screen reports "All N words verified. Your backup
matches this seed." — or lists every missed word number, so you correct
exactly those against the word list. A full pass takes a few minutes;
that is the point — a wrong word in a previously unchecked slot was an
unrecoverable backup waiting to happen.

## Build, CI, releases (v2.4.6-v2.4.7, issue #13 + ROADMAP item 2)

- CI runs the core test suite and builds both firmware variants on every
  push and PR, from a pinned toolchain.
- Reproducible builds: `tools/build-firmware.sh` builds compat + classic
  in a throwaway Debian container from fully pinned tools (arduino-cli
  1.5.1 with its tarball checksum verified in-script, esp32 core 3.3.11,
  TFT_eSPI 2.5.43), with the compile timestamp pinned to the commit's —
  same commit, byte-identical binaries, proven across two cold CI runs.
  See `docs/reproducible-build.md` to verify a released binary yourself.
- Automated releases: merging a version bump to `main` (with its matching
  `docs/releases/vX.Y.Z.md`) now tags, builds, and publishes the release —
  both `.bin`s plus `SHA-256SUMS` — with no human in the loop. This
  release is the first one the pipeline cut for itself.

## Security notes

- No algorithm, storage, radio, or scrubbing changes. The widened quiz
  state stores word positions, never words; the choices buffer is
  unchanged in size and still scrubbed after every step — full
  verification lengthens exposure time, not surface.
- Release binaries are built the same reproducible way as local builds:
  compare what you flash against the published `SHA-256SUMS`.
- Hardware-verified: all interaction changes on a Touch board; marker
  alignment via a forced-non-touch build on the same chassis.
